暨上一章我們講到了系統設計中很重要的資料庫概念，透過主從式架構能夠讓系統使用者即時拿到所需要的資料，那如果有些資料是大眾很常會使用的資料，如果不斷重複資料庫中拿取是不是很麻煩呢，那這時候就需要有快取的功能，將常取用的資料放在快取中讓用戶可以直接存取。

## 1. Scale From Zero to Millions of Users - Part 2

### 快取

所謂的快取，指的就是儲存那些需要大量回應或是頻繁存取資料的一個儲存空間，比起反覆呼叫資料庫更能提升系統的存取效能。**當資料讀取頻率遠高於修改頻率時**，快取最有價值；如果資料變動很頻繁，快取反而會造成一致性問題。

而在系統存取資料時，快取的存取階層高於資料庫，只有在快取中沒有的資料，系統才會在從資料庫中進行讀取。

在使用快取時有幾個注意事項：

- 決定什麼時候開始使用快取（當資料讀取頻率遠高於修改頻率時，才值得引入快取）
- 資料過期的相關規範：一旦資料的存取時間過快取的資料儲存規範就會立刻被移除
- 一致性：快取跟資料庫的資料需要保持一致
- 降低失敗風險：避免出現單一伺服器節點離線（A single point of failure, SPOF），導致整個服務停擺的問題
- 排除策略：要透過什麼樣的演算法排除過期資料，如 LRU、LFU or FIFO 等相關規定。透過 Time-to-Live（TTL）來決定資料要被儲存多久不被清除。

### 內容分散網路（Content delivery Network, CDN）

CDN 主要是透過分散各州的伺服器，運用離用戶最近的伺服器傳送靜態內容，距離越遠，速度越慢。有時若是 CDN 的快取內容沒有所需要的資料，就再往源頭的資料庫找資料，例如 Web Server 或是線上儲存空間如 Amazon S3 等線上服務。

在使用 CDN 服務時有幾項需要考量的問題點：

- 成本花費：CDN 服務通常由第三方廠商提供相關服務，不論存取或是寫入資料到 CDN 伺服器都需要收費。
- 恰到好處的快取過期時間。
- CDN 的相關應對策略：若是 CDN 斷線了改怎麼解決。
- 將檔案無效化（當資料在 TTL 到期前就需要更新時，才需要主動讓快取失效）。
- 透過 CDN 廠商的 API 讓資料無效化。
- 運用版本控制，例如 example1_v1.png、example1_v2.png

而在系統服務中加入 CDN 跟快取的好處如下：

- 靜態資料不再透過 Web Server ，而是透過 CDN 來提升存取效能。
- 透過快取減輕資料庫的負擔。

### 無狀態伺服器

為了能更好擴張網站服務的層級，需要將各個伺服器都改為無狀態伺服器，也就是將**工作狀態資料（ Session data）** 從伺服器中移除，使用者無論連到哪台伺服器，都能從共享儲存（如 Redis）中取得自己的 Session 資料。

而為什麼要採用無狀態伺服器的原因也很簡單，一旦用戶的資料被保存在特定的伺服器中，一旦用戶突然透過別臺伺服器進行連線，那此時用戶有可能就沒辦法存取他自己的資料了。此外，無狀態伺服器的設計也讓系統在增減伺服器時較為簡單。

*註： Session data（工作階段資料）是用於在無狀態的網路協議（如 HTTP）中，追蹤並儲存單一使用者在特定期間內（例如瀏覽網站至關閉分頁）狀態與行為的機制。

至於 Session data 移到**哪裡**？通常會被放在共享資料庫（Shared storage），可以是 Redis 或關聯式資料庫，這樣任何一台伺服器都能讀到同一份 Session。

![無狀態伺服器架構](/blog/sd-stateless-server.png)

一旦網站的線上服務開始走向國際化，為了提升各國的使用者體驗，便需要有多個資料中心來維持服務品質。

### 資料中心

在使用者一般的使用情境下，系統通常是透過地理位置路由（Geo-routed, as known as geoDNS）進行網路流量管理，是一種能根據用戶的地理位置解析其 IP 位址的 DNS 服務。 用戶在存取服務時就可能被分配到不同的資料中心存取資料。

其優勢在於**故障轉移（Failover）** 功能—— 當某個資料中心完全掛掉時，流量可以自動切換到另一個資料中心，這是多資料中心架構最重要的動機之一。
在此基礎上再加上自動擴充功能，系統可以根據流量自動增減伺服器數量，搭配 Load Balancer 就能在不停機的情況下彈性擴張。

![地理位置路由的多資料中心架構](/blog/sd-georouted-datacenter.png)

然而架設多個資料中心也有一些技術挑戰需要克服，例如：

- **網路流量重新導向（Traffic Redirection）**：能將用戶送到地理位置最近的資料中心
- 資料同步：每個資料中心的資料都必須保持**同步**狀態，一旦發生資料中心斷線或是停擺的狀況，最常做的解決方式就是透過多個資料中心去複製遺失的資料。
- 測試與部署：有多個資料中心的情況下，需要在多個地點測試你的網站/應用服務，自動化部署工具也是能讓服務保持一致性的必要工具
