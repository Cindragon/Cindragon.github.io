## The Beginning

When I first started solving LeetCode problems, I could barely handle Easy-level questions. Arrays felt manageable, but anything involving trees or dynamic programming seemed impossible.

Fast forward to today — I've solved over **400 problems** across all difficulty levels, and the journey has fundamentally changed how I think about problem-solving.

## Key Lessons Learned

### 1. Patterns Over Memorization

The biggest breakthrough came when I stopped trying to memorize solutions and started recognizing **patterns**. Most problems fall into a handful of categories:

- Sliding Window
- Two Pointers
- BFS / DFS
- Dynamic Programming
- Binary Search
- Greedy

Once you internalize these patterns, new problems become variations of familiar ones.

### 2. Always Analyze Time & Space Complexity

Before writing any code, I now ask myself:

> "What's the expected time complexity for this input size?"

This simple question often points you toward the right approach before you write a single line of code.

### 3. C++ for Speed, Python for Prototyping

I use **C++** for most submissions because it helps me think about memory and performance. But when I'm stuck on the logic, I switch to **Python** to prototype a solution quickly — its concise syntax makes it easier to experiment.

## Tips for Others

1. **Be consistent** — solve at least one problem every day
2. **Review your solutions** — revisit problems you struggled with after a week
3. **Study editorial solutions** — even when you solve a problem, read how others approached it
4. **Group by topic** — don't jump randomly; focus on one pattern at a time

## What's Next

I'm now focusing on harder graph problems and advanced DP patterns. The journey continues!
