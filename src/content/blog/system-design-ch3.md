# **System Design 筆記 — Ch3：如何開始進行系統設計**

\#\#3. A Framework for system design interviews 系統設計面試時的框架

在面試官詢問到有關如何設計一個系統時，有時候你可能會因為緊張，或是擔心答案不夠完美，而亂了分寸，導致後續的答覆以及結果不甚滿意。然而，其實你不需要這麼想。

現實中所使用的各種網路服務系統其實都超級！超級！超級！複雜。想想看，要你在一個小時左右的面試時間內，設計出如 YouTube、Google、Messenger 等超過好幾億用戶的系統，根本就是天方夜譚。

在面試中，面試官們其實只是想以模擬現實世界中可能遇到的問題為基礎，透過同事之間互相討論的工作模式，試圖想出一個解法來達成目的。換句話說，重點是如何在系統設計的面試問答中，展現出自己的實力，證明自己在壓力下有能力能與他人進行協作，並且精準提問解決目標尚未明確的問題。

此外，有一點很忌諱的就是過度設計。在設計的過程中，應該也要權衡利弊得失，避免過度設計，導致系統複雜度提升，甚至增加額外的支出成本。

\#\#\# 系統設計的四大步驟

筆者整理了四個在系統設計面試時相當實用的四個步驟。  
透過以下的步驟，能幫助你逐步解析面試時所遇到的各項主題，讓你更有信心跟底氣去回覆面試官的問題。

\#\#\# 步驟一：了解問題以及設計範圍

這是第一步也是最重要的一步，在系統設計面試時，切記不要太快給出結論。在尚未釐清需求以目標前就直接回答，可以說是面試時的一個大雷點。

身為工程師，我們要做的事情是精確的提問，做出正確的假設，並且聚集所有需要的資訊來打造我們的系統。你可以向他詢問以下幾種問題：

- 我們具體要打造什麼樣的功能？  
- 這項產品可能會有多少人使用？  
- 公司目前的技術棧為何？  
- 等等

透過問答的方式，向面試官確認各項需求，能讓你設計出更符合面試官心中所想的系統。

\#\#\# 步驟二：提案高層次（high-levle）設計並嘗試說服面試官

在這步驟中，我們要試圖提出一個高層次設計並且與面試官達成共識。

- 提出一個初始概念的藍圖，並且請面試官提出他的想法與回饋，就像是跟同事合作一般。  
- 畫出圖表來表示系統中的各項要素，像是快取、資料中心、伺服器等等。  
- 開始進行估算，把想法大聲說出來，也能讓面試官了解你內心的想法。

若是可行的話，試著帶過幾個使用範例，能幫助你定位設計框架，並且透過 edge case 發現自己可能沒有考慮到的問題。

例如：若是你需要設計一個新聞訂閱系統（News Feed System），這樣的系統設計涵蓋兩個方面：訂閱推廣以及新聞推廣。

- 訂閱推廣（Feed publishing）：當用戶推廣一則貼文，貼文資訊會被儲存在系統資料或快取中，追蹤者們就能被推播到她的貼文  
- 新聞推廣（Newsfeed building）：將朋友的新聞貼文以逆向時間排序的方式聚集並推廣給訂閱者（好友）。

\#\#\# 步驟三：深入自己的設計細節

到了這個步驟，我們應該已經與面試官一起達成了以下共識：

- 確立總體目標以及功能範圍  
- 針對整體設計畫出高層次設計的藍圖  
- 從面試官獲得高層次設計的回饋  
- 根據回饋針對細節設計有進一步的想法

在接下來的過程中，試圖將系統中的幾項元件或是細節做進一步的強化。例如時間管理是一項必要的能力，你必須準備好一些能向面試官證明自己能力的具體證據，並試圖去除設計中一些非必要的支微末節。   
例如，如同上個步驟所說的新聞訂閱系統，可以在針對以下幾點進行更深入的設計：

- 如何獲取朋友 ID  
- 透過 Message queue 排序需求  
- 動態訊息檢索時怎麼進行認證、速率限制是多少 等等

\#\#\# 步驟四：與面試官彙整並總結自己的觀點

在我們費盡千辛萬苦，經過層層討論，終於設計出一個系統之後，我們必須要能將討論的成果進行彙整。面試官可能會希望你指出系統可能的瓶頸或是未來能在改善的地方。千萬別說自己的設計是完美的。這最後一哩路，正是向面試官展現自己批判性思考的大好機會。  
此外，這也是一個向面試官回顧自己設計的好時機，幫助他們留下深刻的印象。

\#\# 總結

筆者整理了幾點在面試中應該跟不應該做的事項，供各位讀者進行參考

\#\#\# 應該：

- 溝通越詳細越好，不要先入為主，認為自己的假設就是對的。  
- 確認了解題目需求再開始設計。  
- 讓面試官了解你的內心想法，把你的構想向面試官溝通。  
- 把面試官當成你的隊友而非敵人，因為你們之後很有可能會一起共事。  
- 不要放棄。

\#\#\# 不應該：

- 面對經典面試題目卻毫無頭緒。  
- 在問題定義尚未完整前即著手設計解法。   
- 針對細節過度設計。應該先看整體架構，而不是細節實作。   
- 不要保持沉默  
- 在面試官說結束之前都還沒結束，請時刻向面試官溝通或是尋求回饋

\#\# 時間分配

最後，筆者能分享一下書中作者提出在一小時的系統面試其時間分配為何。  
（注意！以下時間僅供參考，實際面試時間請以面試當天為主）

Step 1 了解問題以及設計範圍：3-10 分鐘  
Step 2 提案高層次設計並嘗試說服面試官：10-15 分鐘  
Step 3 深入自己的設計細節：10-25 分鐘  
Step 4 彙整總結：3-5分鐘
